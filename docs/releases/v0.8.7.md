## First launch

Nothing here is signed with a paid developer certificate yet.

- **macOS**: System Settings → Privacy & Security → **Open Anyway**, or `xattr -dr com.apple.quarantine "/Applications/Rand Wallet.app"`.
- **Windows**: SmartScreen → **More info → Run anyway**.
- **Linux AppImage**: `chmod +x` it first.
- **Android**: signed with this project's upload key, certificate SHA-256 `75:22:2E:BF:22:D3:95:80:A5:11:2A:AC:B7:EC:2E:03:93:91:07:77:96:E0:45:1D:7B:CF:E3:7E:FA:06:53:52`.

A device that can make a proof (the desktop app, about 8 GiB) makes it. One that cannot — a browser, most phones — uses **the RandProtocol prover** by default (https://prover.randprotocol.org, two machines operated by RandProtocol, no fee), after a one-time notice: like any prover it is sent the wallet's viewing key, so its operators can read the wallet's whole history, and it can never spend. Settings → Prover chooses your own prover instead (the desktop app's **Prove for my other devices**, or your own server), or none ([docs/prover.md](../prover.md)). Details, and how to build every client from source: the [README](https://github.com/randprotocol/clients#readme) and https://randprotocol.org/clients.

## Since v0.8.3

- **Chain 22, constraint set 11.** The core vendors fullnode `v0.8.7` (was `97bcf4b`, constraint set 9): new Poseidon2 round constants (the Grain derivation), a proof-declared Poseidon2 height and the rate-¼ quotient layout. Every note commitment, nullifier, address, key and genesis hash moves, so proofs made by this wallet verify only on chain 22, and chain 21's notes are not carried: chain 22's genesis re-created the operator wallets' balances at their new addresses, and RAND held by other wallets on chain 21 was not carried (the cut record, fullnode `deploy/cut-records/chain22.record`).
- **`deriveKey` for sites** (#16): a site can ask the extension for a key bound to its own origin (durian.market's perps trading keys); the wallet's spend key never leaves it.
- **Audit v14 fixes**: the note-store merge is monotone and a shell without a conditional write merges instead of overwriting (CLI-1001); one wallet per create (CLI-1002); a transfer's outcome follows its phase, so nothing after the broadcast reads as cancelled (CLI-1006); a block whose header announced transactions and whose body is missing no longer reads as empty (CLI-1009); a note is Sent only when this wallet created it (VK-751); retired RandProtocol prover keys are refused wherever they come from (VK-9).
- A withdraw from a browser or phone goes through a prover route (the paired desktop app or the RandProtocol prover), or is refused up front.
