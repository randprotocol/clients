## First launch

Nothing here is signed with a paid developer certificate yet.

- **macOS**: System Settings → Privacy & Security → **Open Anyway**, or `xattr -dr com.apple.quarantine "/Applications/Rand Wallet.app"`.
- **Windows**: SmartScreen → **More info → Run anyway**.
- **Linux AppImage**: `chmod +x` it first.
- **Android**: signed with this project's upload key, certificate SHA-256 `75:22:2E:BF:22:D3:95:80:A5:11:2A:AC:B7:EC:2E:03:93:91:07:77:96:E0:45:1D:7B:CF:E3:7E:FA:06:53:52`.

A device that can make a proof (the desktop app, about 8 GiB) makes it. One that cannot — a browser, most phones — uses **the RandProtocol prover** by default (https://prover.randprotocol.org, two machines operated by RandProtocol, no fee), after a one-time notice: like any prover it is sent the wallet's viewing key, so its operators can read the wallet's whole history, and it can never spend. Settings → Prover chooses your own prover instead (the desktop app's **Prove for my other devices**, or your own server), or none ([docs/prover.md](../prover.md)). Details, and how to build every client from source: the [README](https://github.com/randprotocol/clients#readme) and https://randprotocol.org/clients.

## Since v0.8.0

- **The RandProtocol provers, re-keyed.** On 2026-10-22 the four pinned provers (a, archive2, nyc3, sfo3) were retired. The pool now runs two members, operated by RandProtocol, each with a new key made on its own host: **a** `4SK4-P64N-XWEN-ZSZZ` and **b** `0XZX-NZ1J-SPMB-GWZN`, at `https://prover.randprotocol.org/m/a` and `/m/b`. Wallets pin the pool at build time and never fetch it, so a 0.8.0 wallet finds no member answering with a key it trusts and refuses each one — it can still prove on the device, or with a prover you pair yourself. This release pins the two new members ([docs/prover.md](../prover.md) §8). What they see is unchanged: the wallet's viewing key, never its spend key.
- Nothing else changed: same chain, same core, same keys and note store; no rescan.
- **Private multisig signing is still a preview** (added after release). As in 0.8.0, no proposal signed in these apps has yet been proved and submitted, so a spend from a private multisig account is untested end to end; and the two 0.8.0 faults are still here — a signer profile in the extension, the desktop app or the web wallet cannot be opened after the next lock, and the proposal's fee is not checked against the payments. Do not rely on it until a release says it has been proved.
