## First launch

Nothing here is signed with a paid developer certificate yet.

- **macOS**: System Settings → Privacy & Security → **Open Anyway**, or `xattr -dr com.apple.quarantine "/Applications/Rand Wallet.app"`.
- **Windows**: SmartScreen → **More info → Run anyway**.
- **Linux AppImage**: `chmod +x` it first.
- **Android**: signed with this project's upload key, certificate SHA-256 `75:22:2E:BF:22:D3:95:80:A5:11:2A:AC:B7:EC:2E:03:93:91:07:77:96:E0:45:1D:7B:CF:E3:7E:FA:06:53:52`.

A device that can make a proof (the desktop app, about 8 GiB) makes it. One that cannot — a browser, most phones — uses **the RandProtocol prover** by default (https://prover.randprotocol.org, two machines operated by RandProtocol, no fee), after a one-time notice: like any prover it is sent the wallet's viewing key, so its operators can read the wallet's whole history, and it can never spend. Settings → Prover chooses your own prover instead (the desktop app's **Prove for my other devices**, or your own server), or none ([docs/prover.md](../prover.md)). Details, and how to build every client from source: the [README](https://github.com/randprotocol/clients#readme) and https://randprotocol.org/clients.

## Since v0.8.2

- **Faster proving in the wallet.** The core vendors fullnode `main` `97bcf4b` (was `v0.8.0`): the prover's random columns and Merkle salts are counter-mode ChaCha20 streams filled in parallel, and the preprocessed data is cached per proof shape (fullnode #151). A bundle proof on the desktop app is about 40% faster (19.5 s → 11.3 s for a tier-14 bundle on an M4 Max). The proof format, guests and verifier keys are unchanged, so chain 21's nodes (v0.8.0 to v0.8.2) accept these proofs.
- **A send is not repeated after a dropped connection.** When a node read a `rand_sendTransaction` or a faucet mint and then dropped the connection, the wallet used to treat that as "nothing was sent" and send it again to the next node. It now does that only when the error proves the connection never opened (refused, DNS, unreachable, TLS). Any other connection failure, including a browser's bare "Failed to fetch", is reported as it is, and a read is still asked of the next node.
- **Supply chain.** `k256` 0.14 (RUSTSEC-2026-0387), with the vendored fullnode.
- Same chain, same keys and note store; no rescan.
