# Rand Wallet — browser extension (shared code)

One codebase for Chrome and Firefox, Manifest V3, vanilla JavaScript (ES modules, no bundler,
no framework) so a store reviewer can read exactly what runs. `chrome/` and `firefox/` hold
only a manifest, a packaging script and store notes; `chrome/pack.sh` / `firefox/pack.sh`
copy this directory plus the manifest into `dist/<browser>/` and zip it.

```
shared/
  popup.html/js     the toolbar popup (360×600): lock, home, receive, faucet, activity, settings
  app.html/js       the same screens in a full tab; Send/proving, onboarding and exports run here
  worker.js         Web Worker hosting the wasm core (core/shrugg_wallet.js + _bg.wasm)
  background.js     auto-lock alarm; opens onboarding on first install
  styles.css        design/tokens.json as CSS variables; dark default, light theme
  lib/browser.js    `ext` = browser ?? chrome
  lib/core.js       promise wrapper over the worker: core.keygen(), core.proveTransfer(), …
  lib/rpc.js        JSON-RPC 2.0 client (fetch)
  lib/crypto.js     spend key at rest: AES-256-GCM under PBKDF2-SHA256 (600 000 iterations)
  lib/store.js      storage.local (wallet, vault, settings, note store) and storage.session (unlock)
  lib/wallet.js     scan / send / faucet orchestration (design spec §3.2)
  lib/qr.js         QR encoder (byte mode, level L, v1–40); a ~1.7 KB address is version 30
  lib/format.js     BigInt amount formatting, short forms, elapsed time
  lib/views.js      every screen, hash-routed, shared by popup and app
  icons/            generated by design/make-icons.py
  core/             built by core/scripts/build-wasm.sh (gitignored)
```

## Why Send runs in a tab

A bundle proof is minutes of single-threaded wasm. The popup is destroyed the moment focus
leaves it, so the Send flow opens `app.html#send` in a tab and proves there in a Web Worker;
the tab shows the phase and elapsed time and must stay open until "Submitting…" is done.

## Security

- The spend key is generated inside the core (`keygen`, OS randomness) and stored only as an
  AES-GCM vault under the user's password. The decrypted key lives in `storage.session` (memory,
  cleared when the browser closes) and is removed by the `autolock` alarm.
- The viewing key is derived on demand and shown only behind unlock. Export of the spend key is
  behind unlock and a written warning.
- The only network host contacted is the RPC URL in Settings. Changing it requests an optional
  host permission for that origin. Links to randscan.org open in a new tab; no key is ever part
  of a URL.
- No analytics, no remote code: `script-src 'self' 'wasm-unsafe-eval'`.

## Develop

```bash
core/scripts/build-wasm.sh           # → extension/shared/core/
chrome/pack.sh && firefox/pack.sh    # → dist/chrome, dist/firefox and the zips
```

Load `dist/chrome` as an unpacked extension (chrome://extensions, Developer mode) or
`dist/firefox` via about:debugging → "Load Temporary Add-on…" (pick `manifest.json`).
Point Settings → RPC URL at a node you can reach (a local `shrugg-node`, or an SSH tunnel).
